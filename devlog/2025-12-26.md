The one thing I want to try to remember: I think it's _okay_ if the game ends up being a little bit rube goldberg like. I.e., I'll spawn this thing. Do stuff with it. Then it's responsiuble for spawning this other thing, which does this, and then...

I think it's potentially a bad habit of mine to try to make every little thing in the game some state machine with strong guarantees, perfect cleanup, etc. I think especially for first versions I should be a little bit more hacky.

Another style thought: I think a strong way of organizing style is this:

- Have all the logic for one thing in a file. Always have logic be top-down. Assume that logic in separate files will run in parallel unless explicitly not.
