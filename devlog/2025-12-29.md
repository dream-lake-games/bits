What is the AI interface?

This is actually a delicate question, and impacts how expressive/fun the game AIs are...

NEED to be async, really expressive, and have the harness systems handle the complexity.

I think i probably want to decouple whatever "game state" stuff I feed in from the other types.

Things that the ai will have to do:

- fn from question + game state -> guess
- fn from question + game state + all guesses -> bets

what is the story for how these AI should be allowed to react to bad inputs?

- option A: we expose helper functions "is guess valid", "is bet valid", and rely on them to use it
- option B: the fn signatures above are _actually_ fns that take
  - fn from question + game state + previous guesses (and why invalid) -> guess
  - fn from question + game state + all guesses + previous bets (and why invalid) -> bets

then the expectation would be that the harness is responsible for calling up to X times before giving up. If the ai has to give up, we'd probably want a special input that would short circuit so other players don't have to wait.

i think i also probably just want to be opinionated about any additional fun game "reasoning" state. So along with guess or bets, we have it submit reasoning string, and sources.

the UI story is going to have to get figured out... grr, probably just need to sit down, draw, and figure this out.
